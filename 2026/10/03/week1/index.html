六.简单学习HTTP协议

1. 了解 GET & POST 请求的主要作用与区别
维度 GET (获取数据) POST (提交数据)
主要作用 从服务器获取资源（如浏览网页） 向服务器提交数据（如登录、发帖）
参数位置 拼接在 URL 后面（如 ?id=1） 放在请求体（Body）中
抓包可见性 明文可见，容易被历史记录/日志留存 在Body中，相对隐蔽，但抓包依然可见
幂等性 幂等（重复请求结果相同） 非幂等（重复请求可能产生多条数据）
  1. 了解常见请求头（User-Agent, Cookie, Referer等）的作用
    结合抓包实例，这些请求头是客户端给服务器的“自我介绍”：
  • User-Agent (UA)：告诉服务器我是用什么浏览器/操作系统。安全场景：可修改 UA 伪装成手机端或爬虫，探测隐藏接口。
  • Referer：告诉服务器我是从哪个页面跳转过来的。安全场景：可修改或删除，测试防护机制（防盗链或简单的 CSRF 防护）是否能被绕过。
  • Host：请求的目标域名/IP。安全场景：修改 Host 可能访问到内网或虚拟主机中的其他网站后台。
  • Cookie：客户端本地保存的一小段数据。作用：每次请求自动带上，用于让服务器“认出”你。
  • Accept-Encoding / Accept-Language：告诉服务器客户端支持的数据压缩格式和语言偏好。
  1. 了解鉴权相关的字段 (Cookie, JWT, Session)
    在抓包时，鉴权字段是我们最关注的地方（通常放在 Cookie 或 Authorization 头中）：

Cookie：客户端存储的凭证。请求头中常见 Cookie: PHPSESSID=xxx; 或 Cookie: token=xxx。

Session（会话）：存储在服务器端。服务器生成 Session ID，通过 Set-Cookie 发给浏览器，浏览器保存并在下次请求时带上。特点：服务端有状态。

JWT (JSON Web Token)：一种无状态的 Token。抓包时看：通常出现在 Authorization: Bearer xxx 头中。它由三部分组成（Header.Payload.Signature），Base64 编码，注意 Payload 部分仅仅编码未加密，抓包解码就能看到用户信息。

  1. 了解常见状态码的含义 (200, 302, 403, 5xx等)
    在 BP 的 HTTP History 中，状态码会直观标在旁边，是判断请求成功与否的依据：

  • 200 OK：请求成功，服务器正常返回了数据。

  • 302 Found (重定向)：请求的资源临时移到了别处。抓包场景：登录成功后跳转首页、未登录状态访问后台被踢回登录页。

  • 403 Forbidden：服务器理解了请求，但拒绝执行（权限不够）。安全场景：常用来测试越权漏洞（普通用户尝试访问管理员页面）。

  • 404 Not Found：资源不存在。安全场景：路径爆破时判断目录/文件是否存在。

  • 5xx 服务器错误：

    • 500 Internal Server Error：服务器内部错误。安全场景：提交畸形参数返回500，可能说明存在SQL注入或代码逻辑漏洞。
    • 502 Bad Gateway / 504 Gateway Timeout：网关错误或超时。

    七.简单了解前端三件套

    1. 前端三件套各自的作用（核心比喻：建房子）

  • HTML (超文本标记语言)：骨架/结构。定义网页的标题、段落、图片、链接和表单。没有HTML，网页就是一片空白。

  • CSS (层叠样式表)：皮肤/表现。负责排版、颜色、字体、大小。让网页变得好看。

  • JavaScript (JS)：行为/动作。负责网页的动态交互，比如点击按钮弹窗、数据实时加载、鼠标悬停效果。

2. 前端是如何构成的？（浏览器渲染流程）
当你在浏览器输入网址后：

  1. 浏览器向服务器发送请求。
  2. 服务器返回 HTML、CSS、JS 文件。
  3. 浏览器解析 HTML 构建 DOM 树，解析 CSS 构建 CSSOM 树。
  4. 结合成渲染树，浏览器开始绘制页面，最后执行 JS 让页面“活”起来。

八.熟悉使用F12之后的浏览器原生的devtools

什么是DevTools？：按 F12 打开的浏览器自带“透视镜”和“工具箱”，不用启动BP也能看网页底层数据。

常用模块及作用：

  1. Elements (元素)：查看/修改实时HTML和CSS。安全用法：双击修改代码绕过前端限制。
  2. Network (网络)：查看所有网络请求。安全用法：过滤 Fetch/XHR 找核心接口，点击请求后在右侧 Headers 面板看请求头（User-Agent, Cookie等）和请求体参数。
  3. Console (控制台)：执行JS代码，看报错。安全用法：输入 alert(1) 测试XSS。
  4. Application (应用)：查看和修改本地存储。安全用法：查看/修改Cookie、Token，测试越权和鉴权。
  5. Sources (源代码)：查看加载的JS文件。安全用法：按 Ctrl+F 搜索 key、password、api 找敏感信息。
